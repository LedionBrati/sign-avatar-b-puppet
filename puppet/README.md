# puppet/

Motion JSON ([`motion/FORMAT.md`](../motion/FORMAT.md)) → landmark debug view + VRM puppet, in the browser and as offline mp4 renders at the avatar framing (540×720, 24 fps, waist up).

```bash
cd puppet && npm install && node fetch-model.mjs          # VRM sample model -> puppet/models/ (git-ignored)
npm run dev    # http://127.0.0.1:5181/?motion=out/motion/judy.clean.json&video=references/how2sign/judy.mp4
cd .. && node puppet/render.mjs --motion out/motion/judy.clean.json --view sidebyside --video references/how2sign/judy.mp4 --closeup --out out/puppet/judy-sidebyside.mp4
npm test && npm run typecheck                               # in puppet/
```

- **Viewer params:** `motion`, `video` (paths relative to the repo root, or absolute), `view=sidebyside|skeleton|vrm`, `closeup=1`, `solver=direct|kalidokit`, `mannequin=1`, `smooth=0` (raw puppet, see below). Keys: space play/pause, ←/→ step. Without `motion` it plays the synthetic fixture `fixtures/wave.json` (`npm run fixture` regenerates it).
- **Smooth playback (default):** every frame is solved once, then the bone rotations are cleaned over the whole clip ([`src/track.ts`](src/track.ts)): tracker glitches out (a joint that leaves its path and comes back faster than it can move, e.g. a hand read inside out for 1-3 frames; a whole hand is repaired together when its wrist glitches or 5+ of its joints glitch at once), tracking dropouts bridged (up to 0.5 s) or eased to rest and back (no snaps), and a light zero-phase smoothing (no lag, held handshapes stay exact). The viewer plays the result between frames on every screen refresh, with hair and cloth physics. The status line and `<out>.json` say how many bone-frames were repaired. `smooth=0` / `--raw` shows every frame exactly as tracked. On Judy: max one-frame arm/wrist jump 177° → 66°, frame-to-frame jerk about halved, fingers outside the glitch frames within 2.3° (median) of the landmarks.
- **render.mjs** steps `window.renderFrame(i)` in headless Chrome (software WebGL), pipes PNGs to ffmpeg (libx264, yuv420p) and checks the frame count with ffprobe. Frame i of the video is motion frame i, smoothed or `--raw`. `--view vrm` is clean (no overlays), for the repaint. It also writes `<out>.json`: tracking failures (part missing) vs retargeting errors (avatar bone vs landmark, degrees) of the rendered pose, plus `smoothing`. Chrome path: `CHROME=...`, else the standard install locations (`shared/find-chrome.mjs`, used by every headless-Chrome script). ffmpeg / ffprobe: `FFMPEG` / `FFPROBE`, else PATH, else the binaries bundled in `pipeline/` after its `npm install` (`shared/ffmpeg.mjs`, used by the puppet, pipeline and examples scripts).
- **Solvers:** `direct` (default for a .vrm) aims every bone at the landmarks, fingers included (curl and spread, palm normal for the hand, whose roll goes to the forearm: a wrist cannot roll). `kalidokit` is the GSL-repo approach (curl only, heuristic arms), kept for comparison. `anatomic`: see below. Code: `src/motion.ts` (format), `src/blend.ts` (sentence blending), `src/skeleton.ts` (2D view), `src/vrm.ts` (puppet), `src/track.ts` (clean-up).
- **Realistic signer (`--avatar signer`, viewer `avatar=signer`):** `models/signer.glb`, a MakeHuman woman (CC0) in a black long-sleeve top with skin-tone hands, soft light and the target photo's framing. Build it with `node avatar/build.mjs` ([`avatar/README.md`](avatar/README.md)). Its default solver is `anatomic` ([`src/hand.ts`](src/hand.ts)): every finger joint inside anatomical limits, IK to the fingertips, no fingers inside each other, one-euro smoothing, palm flips from the tracker repaired. A motion v2 `hands3d` is used for the fingers when present. `render.mjs` reports `hand joint-limit violations` and overlapping fingers for any avatar.
- **Passes and speed:** `--passes rgb,depth,normal,seg` writes frame-aligned `x.mp4`, `x.depth.mp4`, `x.normal.mp4`, `x.seg.mp4` (per-finger colours) from one camera. `--view vrm` now captures with the browser's JPEG encoder, 24 frames per page call (`--capture png` is the old path); `--workers N` renders on N Chrome processes; `--gpu` uses the laptop's Intel GPU. Numbers: [`experiments/2026-11-16-realistic-reference-avatar.md`](../experiments/2026-11-16-realistic-reference-avatar.md).
- **Instant player:** [`src/player.ts`](src/player.ts) (`SignerPlayer`) plays a motion or a sentence of sign motions on a canvas right away, for `app/web`. `npm run build:player` bundles it to `dist/signer-player.js`; `player.html?signs=a.json,b.json` is a demo; `node scripts/player-check.mjs a.json b.json` times it.
