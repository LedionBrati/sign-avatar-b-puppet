## Browser evidence and fixes

Chrome initially reproduced a critical failure: after `Turn right at the bank.`, the previous video frame remained visible, the summary still said “Signed,” and no ambiguity reason appeared. The screenshot is in the local ignored QA log (`out/qa-logs/baseline-ambiguous.png`). The patch clears the player queue for blocked or failed requests, shows the complete current caption and reasons, removes stale hints, and resumes from a fresh queue. The shared client also fails closed if an older API omits `safety`. The visible status handling applies to the extension and mobile app without changing their overall layouts.

Web browser automation also passed: empty submit disabled; blocked request while a previous clip was playing stopped both videos; a later supported request resumed; simulated network failure showed the original caption and cleared the queue; later network recovery cleared the error banner; a legacy API response without `safety` stayed caption-only. No uncaught page errors were observed in the corrected run. The extension Chrome verifier passed initial playback, blocked ambiguity with empty video queue, resumed playback, caption-source playback, drag/snap, and popup health. Mobile web export played the synthetic HELLO video in Chrome (unpaused `currentTime` advanced), then passed supported → ambiguous → supported and caption-only negation with no page errors. Native mobile video playback was not tested.

## Reproduce

From the repository root, install the lockfile dependencies once:

```sh
(cd translate && npm ci --no-audit --no-fund)
(cd app/core && npm ci --no-audit --no-fund)
(cd app/web && npm ci --no-audit --no-fund)
(cd app/extension && npm ci --no-audit --no-fund)
(cd app/mobile && npm ci --no-audit --no-fund)
(cd puppet && npm ci --no-audit --no-fund)
```

Run the checks:

```sh
node --test translate/test/*.test.mjs shared/*.test.mjs app/server/test/*.test.mjs
(cd puppet && npm test && npm run typecheck)
(cd app/core && npm run typecheck)
(cd app/web && npm run build)
(cd app/extension && npm run build)
(cd app/mobile && npm run typecheck && npx expo install --check && npm run export:web)
```

For isolated API/browser QA, use an installed `ffmpeg` on `PATH`, or set `FFMPEG` to a local binary. The server's MP4 join command also requires `ffmpeg` on `PATH`. In this run, `ffmpeg-static` already present in a separate local pipeline checkout supplied the binary; nothing was installed globally.

On this Mac the exact binary was `/Users/alexandrosnomikos/Documents/hackathon/demo-vocabulary/pipeline/node_modules/ffmpeg-static/ffmpeg`. I ran the generator with `FFMPEG` set to that path and started the server with its parent directory prepended to `PATH`.

```sh
node app/server/scripts/make-qa-clips.mjs out/qa-clips
CLIPS_DIR="$PWD/out/qa-clips" SEMANTIC=0 PORT=8787 node app/server/index.mjs
# second terminal:
(cd app/web && npm run dev -- --host 127.0.0.1)
# third terminal:
node app/server/scripts/qa-api.mjs
(cd app/web && node scripts/qa-safety.mjs)
```

For the extension verifier, set `CHROME` to the Chrome executable and `QA_SHOTS_DIR` to an ignored output directory so teammate screenshots in `app/extension/docs/` are untouched:

```sh
(cd app/extension && CHROME='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' SIGNLAYER_API='http://127.0.0.1:8787' QA_SHOTS_DIR="$PWD/../../out/qa-logs/extension" npm run verify)
```

For exported mobile web QA, serve `app/mobile/dist` on port 5174 and open `http://127.0.0.1:5174/?server=http%3A%2F%2F127.0.0.1%3A8787` in Chrome. Native Expo playback needs a device or simulator and the same API reachable over LAN.

## Remaining blockers and limits

1. **Real avatar clips absent here.** The synthetic fixture proves API/player wiring only. It cannot establish sign accuracy, transitions, or the hackathon demo's visual quality.
2. **Signer review absent.** `fully_supported` is a structural playback status, not ASL certification. Homograph senses and semantic substitutions remain conservative.
3. **No native device or real microphone QA.** Expo web and headless Chrome do not cover native `expo-video`, device permissions, or speech recognition accuracy.
4. **Long selected text in the extension.** The extension currently normalizes whitespace and truncates selection text before API submission; long messages need a separate product decision. This QA patch did not widen the API's 500-character limit or silently add a partial-signing mode.

No restricted WLASL media, derived motion, API keys, or paid model calls were added or used by this QA work.
